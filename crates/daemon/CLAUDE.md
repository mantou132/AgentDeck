# AgentDeck Daemon (`crates/daemon`)

后台守护服务 `agentdeckd`：管理本地 ACP Agent，提供文件与 Git 接口，经 Relay 连接多台远端设备。

## 代码导航

- `src/main.rs`：CLI 与前台运行入口，负责状态输出和配对二维码。
- `src/app_data.rs`：唯一的本地存储布局定义（`AppPaths` / `AgentPaths`）；路径方法没有文件系统副作用，写入方自行创建目录，清理复用同一套路径定义。
- `src/config.rs`：Pairing ID 生成、Relay 默认值和 `daemon.json` 持久化。普通启动会合并已保存的配置；reset 从默认值加显式参数重建，只保留 `features`（描述主机而非配对）。
- `src/daemon.rs`（子模块 `daemon/`）：服务生命周期。`reset.rs` 编排重置；`singleton.rs` 是 `daemon.lock` 单例锁；自启在 macOS / Linux 用 `service_mgr.rs`（LaunchAgent / systemd --user），Windows 用 `windows.rs`（计划任务）。macOS 的 plist 由 daemon 自己生成，内容未变且已加载时 start 不重写、restart 用 `launchctl kickstart -k`，因为重写 LaunchAgent 会再弹"后台项目已添加"通知；`stop` 仍会删除 plist。
- `src/awake.rs`（子模块 `awake/power.rs`）：防自动睡眠（`agentdeckd awake` CLI、后台监控与外接电源检测）。
- `src/acp_agent/`：`acp_agent.rs` 是 ACP 客户端入口，`AgentSessionManager` 对外提供会话接口；`runtime.rs` 是每种 Agent 共用的子进程与连接生命周期（`AcpRuntime`）；`session.rs` 是每个会话一个的 actor（带 `epoch` 与自增 `seq` 的有界事件日志及流式文本 chunk 合并、多设备订阅者、后台回合执行、未作答请求、`agent_session_open` 增量/全量回放）；`meta.rs` 持久化主机级会话元数据 `session_meta.json`（`title`、`updatedAt`、软删除 `deleted`、`unread`，reset 保留）；`provision.rs` 下载预编译 Agent；生命周期与并发测试在 `lifecycle_tests.rs`。`catalog.rs`：Agent 注册表（启动 Agent 时后台拉取官方 CDN 存为 `registry.json`，不等网络）、自定义 Agent（`custom_agents.json`，`{ id, name?, command?, args? }`，只有 `id` 时取注册表同名 Agent，同 id 的 `command` 覆盖注册表；reset 保留，只有它们下发给客户端）与 `agentdeck_env`（Codex 用 `CODEX_CONFIG` 关闭 `visualize`）。内置 Agent `free` 复用托管的 `opencode` 二进制，经 `OPENCODE_DB` / `OPENCODE_AUTH_CONTENT` / `OPENCODE_CONFIG_CONTENT` 与用户的 OpenCode 隔离（只用免费 provider，挂载全部已开放 skill）；不用 XDG 变量，因为它们会传给 Agent 执行的命令。
- `src/agent_rpc.rs`：远端 RPC 入口，注册全部处理函数并做参数校验；`agent_rpc/files.rs` 是目录补全、浏览与文件读取，`git.rs` 是 Git 接口与会话列表的 worktree 识别，`prompt.rs` 组装 prompt（面板系统提示、语音标记、附件落盘）。
  `peer_attach()` 是 attach 的业务部分：解析并过滤客户端声明的 skill，回复带 `version`（`CARGO_PKG_VERSION`，发布时由 `release.yml` 按 tag 写入 `Cargo.toml`），App 据此提示升级；还带 `customAgents`（`custom_agent_list()`），App 把它们列在 `free` 之后；带 `restrictedFeatures`（客户端声明的 skill 中未开放的），App 据此禁用。
- `src/relay.rs`（子模块 `relay/{codec,encryption}.rs`）：`RemotePeerManager` 在一条 Relay 连接上复用多台设备，维护 deviceId → peerId 映射（`remote_peers_v1.json`）；处理 `peer_attach` 时只分配 peerId、保存 skill 并回复。请求带 `ephemeral: true` 时，记录 `(peerId, id)`，该请求的 event 与最终回复也以 ephemeral 发出。每次连上 Relay 以 ephemeral 广播 `host_reconnected`，供不支持 presence 的 App / Relay 重新 attach。
  `relay/codec.rs` 负责 RPC 消息与 Relay 帧互转（加密、帧大小限制与超限错误回复；带字节的回复总是拼成二进制帧 `[u32 头长度][回复 JSON][原始字节]`，加密为 `[nonce][密文]`，AAD 带 `binary` 标签，Relay 按 ephemeral 投递，不涉及 peer 与设备）；`relay/encryption.rs` 为 XChaCha20-Poly1305 + HKDF-SHA256 端到端加密原语。
- `src/peer.rs`：JSON RPC 对端。`handle_with_bytes` 注册的处理函数可在结果旁返回原始字节（如 `file_read` 的图片与 raw 读取），由传输层携带，对端在 `result.data` 收到；结果本身不放 `data`，也不做 base64。失败回复为 `{ id, error, code? }`：`handle_rpc` 的处理函数可附 `code`；Agent 返回 ACP `AuthRequired` 时，后台回合在 `turn_ended` 事件与 `agent_session_state` 通知里附 `code: "auth_required"`，App 据此提示用户在电脑上登录该 Agent（SDK 的 `start_session` 会把 `session/new` 的错误变成 internal error，所以创建与加载会话拿不到这个码）。
- `src/push.rs`：向会话设备推送 FCM 通知，两种类型（`PushKind`）：prompt 成功完成（`response_complete`，被取消的回合不发，发给发起该 prompt 的设备，正文 `notification_response_complete`），以及回合在等权限请求或问题（`input_request`，与 `agent_permission_request` / `agent_elicitation_request` 通知一起广播给设备，正文 `notification_input_request`）。正文由 App 本地化（Android strings、iOS `Localizable.strings`），新增类型要同步原生文案，只能随商店版本生效；同一会话的新通知替换旧通知；`data` 带 `type`、`host`（`push::host_key`，配对 ID 的 SHA-256 前 8 字节，不泄露配对 ID）、`agent` 与 `sessionId`，供 App 点击通知时打开会话。
- `src/screen_capture.rs`（子模块 `screen_capture/{ios,android,browser}.rs`）：`screen_capture`（单帧）、`screen_stream`（实时推流，带静止帧哈希过滤、Nearest 缩放加速与不透明每流 `replace_key` 供 Relay 覆盖未发旧帧）与 `screen_input`（归一化点击输入），按 target 捕获（`ios:` 单帧及流首帧用 `simctl` PNG alpha 遮罩取得屏幕形状，后续流帧直接用 `simctl` JPEG，因当前 Xcode 的 `simctl -` 会写出 `./-` 文件故保留短生命周期临时文件；缓存 `simctl` 路径以跳过每帧 `xcrun` 查找；`android:` 缓存 `adb` 路径与 `dumpsys display` 形状（仅首帧及分辨率变化时刷新），优先用原始帧 `adb exec-out screencap` 单遍缩放编码 JPEG，无法识别时回退 `screencap -p`，点击走 `adb shell input tap`；`browser:` 用 rmcp 连 browser4agent 本地 MCP 服务 `127.0.0.1:39271/mcp`，以页面脚本判断标签页是否在模拟手机，点击复用活跃流的 MCP 连接与按帧尺寸缓存的 viewport，优先经 `execute_script_in_background` 单次批量派发 CDP `Input.dispatchMouseEvent` 并在失败或首次附加时回退 `debugger_send_command`，流关闭时 detach），缩放后以 JPEG 字节二进制帧回复。
- `src/render_skills.rs`：skill 文件与 `--features` 功能过滤。skill 由 App 提供（源码在 `packages/agentdeck/skills/`），daemon 不内置 skill 与组名。`--features`（逗号分隔的功能或组名，`all` 取消限制，存 `daemon.json`）按客户端在 `peer_attach` 的 `skills.groups` 声明（`basic` / `desktop`）过滤向客户端开放的 skill，不传则全部开放。`peer_attach` 的 `skills.hash` 是内容哈希，本机没有该版本时回复 `skillsMissing: true`，App 随即用 `skills_install`（`{ hash, files }`）发来，写到 `AppPaths::skills_dir()/versions/<hash>/<能力>/{.agents,.claude}/skills/<能力>/`（先写临时目录再改名，只保留最新 3 个版本）。文件中的 `{{LEARNED_PATH}}` 替换为跨版本保留的 `learned/<能力>/learned.md`，该目录随 skill 一起挂载，供 Agent 写入（哪些 skill 用它由 skill 文件决定，daemon 不按名称区分）。
- `src/tasks.rs`（子模块 `tasks/schedule.rs` 负责 `Schedule` 时间计算与校验）：定时任务（#34）。`tasks.json` 存任务，`task_runs/<id>.jsonl` 存运行记录（路径在 `AppPaths`）。调度每 30 秒对一次挂钟时间而不是睡到下次运行，因为电脑睡眠时单调时钟停走；每个计划时间只触发一次，错过不超过 6 小时的（睡眠、daemon 未运行）补跑一次，更早的跳过；新建、修改或重新启用的任务从下一个时间开始（起点存为任务的 `scheduledFrom`，重启后仍有效）。`daily` 计划必须带 IANA `timeZone`（保存卡片的设备时区，即用户的时区），按该时区的日期、星期与时刻执行（`chrono-tz`，夏令时跳过的时刻当天不跑），与主机时区无关；调度内部一律用 UTC。一次运行：用最近一次 attach 的 skill 新建会话（`remote_app` 系统提示加无人值守说明），按 `configOptions` 设置会话选项后 prompt；会话宿主使用广播（`TaskHost`，由 `RemotePeerManager` 实现：通知所有已 attach 的设备，权限请求、问题与完成推送到 30 天内 attach 过且有 token 的设备（`remote_peers_v1.json` 记 `attachedAt`），推送 `data` 带 `taskId`：运行中的任务会话拒绝设备 `agent_session_open`，App 在任务页作答），会话以 `input_timeout` 创建并开启 `auto_approve`（权限请求自动以 allow 选项放行，不打扰设备；问题超时 30 分钟被拒绝，见下方等待用户输入）；超过 `timeoutMinutes` 取消，失败按 `retries` 重试；运行摘要 `summary` 取回复中最后一个 `agentdeck-speech` 注释（无人值守说明要求以它写一句结果），没有时（不读系统提示的 Agent）取 HTML 注释之外的最后一个非空行，截到 200 字；结束后关闭会话并推送完成。成功的运行保留最近 20 次、失败的保留 90 天，删记录时连同会话删除。删除任务会停止正在进行的运行，这次运行不留记录和会话，也不推送。RPC：`task_list`（附 `nextRunAt`、`lastRun`、`running`，以及这次运行的会话建好后的 `runningSessionId`）、`task_runs`、`task_upsert`、`task_set_enabled`、`task_run_now`、`task_delete`；变化时广播 `task_updated`（`{ id }`）；`agent_session_list` 给运行产生的会话附 `task: { id, name }`。
- `src/logger.rs`：`tracing` 日志（含依赖库事件）按天写入 `logs/agentdeckd.YYYY-MM-DD.log`，保留 7 个文件；默认 `info`，`RUST_LOG` 可覆盖；只在 `run` 中初始化，不输出到终端。

## 约束与现状

- **端到端加密**：`adk1_` 配对必须加密，Relay 只做帧路由，禁止自动退回明文。
- **信任模型**：Pairing ID 是唯一凭证，所有设备共用同一把密钥，deviceId 由设备自报，不能按设备吊销（只能 `reset` 整体轮换）。所有设备共享全部会话。文件和 Git 接口直接使用客户端传入的路径，**没有目录限制**；`file_read` 带 `raw: true` 时，任意文件都返回原始字节（`type: "binary"`，附文件总大小 `size`），供 App 预览协议使用；再带 `offset` + `length` 时只读该片段且不受整文件 8MB 上限约束（单片仍不超过 8MB），用于视频等媒体的 Range 请求。
- **工具图片瘦身**：转发 `tool_call` / `tool_call_update`（含 `open` 回放）前，删除 `content` 与 `rawOutput` 中图片的 base64 数据（`update_to_json`）。App 不渲染工具图片，而截图类结果会让回放达到几十 MB，堵住有序的 Relay 队列。
- **文件附件**：`agent_prompt` 的 `{ type: "file", name, data, mimeType }` 附件解码后写入系统临时目录 `agentdeck-attachments/<时间戳>/<文件名>`（文件名中的空白与 `()[]<>` 替换为 `_`），以 `file://` ResourceLink 交给 Agent 自行读取；由系统清理临时目录，daemon 不删除。不用 ACP blob resource，因为 claude-agent-acp 会丢弃它。
- **会话状态与订阅**：会话 actor 由 daemon 持有并维护唯一 `epoch` 与自增 `seq` 的有界事件日志（连续 `agent_message_chunk` / `agent_thought_chunk` 自动合并）。`agent_session_open` 是幂等的：actor 尚未存在时先占位再向 Agent `session/load`（`freshLoad: true`）；已存在且 `sinceEpoch` 匹配、日志未溢出时仅回放 `seq > sinceSeq` 的增量事件（`fullReplay: false`），否则全量回放（`fullReplay: true`），回放事件按字节上限打包成 `{ events }` 批量帧发送；同时登记调用设备为订阅者并返回快照（`epoch`、`seq`、`running`、`userInputs`、`modes`、`configOptions`、`suggestion`）。`agent_session_unsubscribe` 只移除该设备订阅，不影响会话与回合。`agent_prompt` 是短 RPC：校验并启动后台回合后立即返回 `{ ok, agent, sessionId }`，同一会话的回合互斥；回合在 actor 内推进并记录 `turn_started`、回显带 `clientMessageId` 的用户消息、各类 `session_update` 与 `turn_ended`，向所有订阅者推送 `agent_session_event`，回合起止与标题变更更新 `updatedAt` 并广播 `agent_session_state`；回合超过 `timeoutSeconds` 没有任何 update 即取消并结束。`agent_active_sessions` 返回所有活跃/运行中会话与全部未作答 `userInputs`，供设备重连或切换 host 后对账。会话 list / create / open 遇到 Agent 未启动时先安装或启动，期间定时发 `agent_status` 帧（App 据此显示状态并续期），调用的 `timeoutSeconds` 从就绪后起算。
- **主机级会话元数据**：`session_meta.json`（`SessionMetaStore`，reset 保留）按 `(agent, sessionId)` 记录 `title`、`updatedAt`、软删除 `deleted` 与 `unread`，补齐不返回 `updatedAt` 或只给占位标题（如 `Session <8位hex>`）的 Agent 并跨设备同步已读状态。创建、首条 prompt、回放首条用户消息、回合起止（非定时任务的正常完成置 `unread: true`，新回合清零）、标题更新与分支时更新并持久化；`agent_session_list` 用它过滤软删除项、补标题、取 `max(daemon.updatedAt, acp.updatedAt)` 并附 `unread`；`agent_session_set_unread` 修改并广播 `agent_session_unread`（不依赖 live actor）；`agent_session_delete` 关闭 actor、写入软删除并在 Agent 声明支持时尝试 ACP `session/delete`，随后广播 `agent_session_deleted` 供多端同步移除。
- **等待用户输入**：权限请求（`session/request_permission`）与问题（`elicitation/create`，`initialize` 只声明 `elicitation.form`，claude-agent-acp 因此启用 `AskUserQuestion`）走同一套：daemon 加 `requestId` 按会话保存，向所有设备广播 `agent_permission_request` / `agent_elicitation_request`，任意设备用 `agent_user_input_respond`（`{ agent, sessionId, requestId, response }`）作答；已作答或被取消时广播 `agent_user_input_resolved` 供其余设备关闭卡片；`agent_active_sessions` 与 `agent_session_open` 快照都附带 `userInputs`。有请求等待时空闲计时暂停（用户可能比 Agent 允许的沉默时间更久才作答），作答后重新计时。默认不设作答时限，回合取消、会话关闭或空闲超时都按取消结束；`SessionContext.input_timeout`（定时任务的运行用 30 分钟）到期时由会话 actor 拒绝：权限请求选其 `reject_once` / `reject_always` 选项（直接取消在 claude-agent-acp 里会变成请求失败），问题回空响应即取消，Agent 读到拒绝后继续。
- **子代理会话**：按 ACP Subagent Sessions RFD（`unstable_subagents`），连接级处理器把子会话（可嵌套）登记到根会话（`AcpRuntime::children`），其 update、权限与问题都经根会话转发并带 `childSessionId`。`agent_prompt_cancel` 带 `childSessionId` 时只在子会话声明了 `cancel` 时发送。不持久化子会话（claude-agent-acp 在 `session/load` 回放中重放），也不 prompt / open 子会话。OpenCode 不认标准字段，只在 `clientCapabilities._meta["opencode/child-session-updates"]` 为 `true` 时才上报子会话，因此 `initialize` 同时带这个键（其他 Agent 忽略）。
- **配置**：`daemon.json` 自启时读取；Relay 配置变更需要重启，awake 配置会自动重载。显示 Pairing ID 时必须带安全警示边框。配对二维码为 `agentdeck://connect?pairingId=…`，使用非默认 Relay 时追加 `relayUrl`。
- **防自动睡眠**：默认和 reset 后均为 `never`。`active` 以最后一次 RPC 收发时间计时，一小时无 RPC 后释放；状态写入 `awake_status.json`，daemon 退出时清理。
- **reset**：停止服务并持锁后，删除 `remote_peers_v1.json`、`logs/` 和 `agents/*/install/`；未传 `--pairing-id` 时生成新的 `adk1_` ID，未传 `--relay-url` 时恢复默认 Relay，`--features` 保留原值。保留已安装的 Agent 及其历史，完成后恢复原来的运行/停止状态，并输出 status。
- **会话指令**：面板上下文等指令一律通过 `session/new` / `session/load` 的 `_meta.systemPrompt.append` 与 `_meta.antigravity.systemPrompt.append` 下发，不判断 Agent 能力。OpenCode（含 `free`）忽略该字段，面板上下文对其不生效。不要用 MCP instructions 承载客户端上下文（语义不符，Codex 也不会当作指令）。正式字段见 RFD agent-client-protocol#1237。
- **下一句建议**：`session/new` / `session/load` 一律在 `_meta.claudeCode` 中开启 `promptSuggestions`，并用 `emitRawSDKMessages` 只订阅 `prompt_suggestion`（claude-agent-acp 默认丢弃），与 `systemPrompt` 一样不判断 Agent，其他 Agent 忽略该键。建议在回合结束后以 `_claude/sdkMessage` 到达，保存在 actor 中（供 `agent_session_open` 返回）并以 `agent_prompt_suggestion` 通知广播给设备。
- **关闭冲突的自带 skill**：同一 `_meta.claudeCode.options.settings` 以 `skillOverrides` 关闭 Claude 自带的 `dataviz`（与 chart 冲突），只作用于该会话，不改用户配置；Codex 的 `visualize` 见 `agentdeck_env`。
- **会话列表的 worktree**：cwd 在 git linked worktree 的会话附上 `worktree: { mainCwd, name }`；worktree 已删除时退回识别 Claude Code 的 `<repo>/.claude/worktrees/<name>`。
- **分支会话**：`agent_session_fork` 发送 ACP `session/fork`（`unstable_session_fork`），不建 actor，客户端随后照常 open；daemon 记录并返回 `title` 与 `updatedAt`。分支点用 claude-agent-acp 识别的 `_meta.jetbrains.air.fork`，其他 Agent 会复制整个会话。
- **回合间的会话更新**：会话 actor 空闲时也读取 ACP session update（如 `session/new` 返回后才推送的 `available_commands_update`），按序写入事件日志并以 `agent_session_event` 推送给订阅者。
- **语音对话**：`agent_prompt` 带 `voiceChat: true` 时在附件末尾追加 `<agentdeck-voice-chat/>` 标记；`remote_app` 系统提示说明见到标记要在回复末尾写 `<!-- agentdeck-speech … -->` 注释作为朗读摘要（读取系统提示的 Agent 如 Claude、Antigravity 会遵循）。客户端从历史用户消息中去掉该标记。
- **Skill 挂载**：客户端在 `peer_attach` 带 `skills: { hash, enabled, groups }`（版本、开启的 skill 与分组），daemon 去掉 `--features` 未开放的后按设备保存，对声明了 `sessionCapabilities.additionalDirectories` 的 Agent 把该版本对应的 skill 目录传给 `session/new` / `session/load`；其他 Agent 不注入。OpenCode 只把这些目录当作访问授权，不从中加载 skill，所以 `free` 另在进程级挂载最近一次 attach 所用版本的全部已开放 skill，开关对它不生效。

## 常用命令

- `cargo check -p agentdeck-daemon` / `cargo test -p agentdeck-daemon` / `cargo build --release -p agentdeck-daemon`
- CLI 用法以 `agentdeckd --help` 为准。

## npm 分发（`npm/`）

- 主包 `agentdeckd` 通过精确版本的 `optionalDependencies` 引用四个平台包（darwin-arm64/x64、linux-x64-gnu、windows-x64）。平台映射在 `npm/platforms.mjs`，新增平台时同步 Release 的 Rust matrix。包里没有 postinstall，安装后不会自动启动服务。
- 构建与验证：`build.mjs`（校验 SHA-256、生成并 pack）、`verify.mjs`（从本地 registry 安装并执行 `--help`）、`distribution.test.mjs`（完整安装行为测试，需要 zip）。
- 发布：推送 `v*` tag 后由 `release.yml` 通过 OIDC Trusted Publisher 发布，不使用 `NPM_TOKEN`。先发平台包，最后发主包；预发布版本用 `next` tag，正式版本用 `latest`。新增包需要先由维护者用 `publish.mjs` 初始化，再在 npm 上配置 Trusted Publisher（`mantou132/AgentDeck`，`release.yml`）。
